# Видео кодом по примеру или сценарию

Ролик рисуется покадрово одним Python-файлом: без видеоредактора, плагинов
и готовых футажей. Звук тоже синтезируется. В комплекте: готовый рендерер
с библиотекой из 9 сцен, анализатор примера и проверка результата.

Путь скилла ниже — `SKILL` (папка, где лежит этот файл).

## Вход: один из трёх режимов

- **A. Пример видео** (файл, ссылка на Диск): сделать аналог.
- **B. Сценарий текстом** (абзац, список по секундам, таблица): сделать ролик.
- **C. Пример + правки** («как в этом, но подпись X и текст про Y»):
  разбор примера задаёт форму, правки — содержание.

## Рабочий процесс

1. **Получить видео** (режим A/C). Файл из Диска скачивать штатным
   инструментом Диска в рабочую папку; оригинал не коммитить.
2. **Разобрать пример**: `python3 SKILL/scripts/analyze.py ВИДЕО --out анализ`
   и заполнить таблицу сцен по кадрам — методика и эталон разбора:
   `references/analysis.md`. Смотреть не только секундные кадры, но и
   границы сцен (там глитчи и вспышки).
3. **Зафиксировать план** таблицей «время → сцена → текст → эффект»:
   в режиме A — конструкция примера с заменой текстов/подписи,
   в режиме B — нормализация текста пользователя.
   Подпись автора оригинала не копировать; автора аналога брать у
   пользователя/из контекста. Спрашивать только то, что нельзя infer
   (см. `references/scenario-format.md`, раздел «Когда спрашивать»).
4. **Собрать JSON-конфиг** по `references/scenario-format.md`
   (образцы — `examples/`). Числа в кадре делать честными: кадры =
   секунды × fps, частицы = параметру сцены, «строк кода» = `auto`.
   Новой сцены не изобретать, пока хватает библиотечной (`big_text`
   покрывает большинство текстовых сцен).
5. **Черновик**: `python3 SKILL/scripts/render.py config.json --preview --out out`
   → посмотреть раскадровку и полные кадры спорных сцен; поправить конфиг
   (реже — код). Что и где крутить: `references/renderer-guide.md`.
6. **Полный рендер** (без `--preview`), затем
   `python3 SKILL/scripts/verify.py out/клип.mp4 --expect config.json`
   и ручной чек-лист `references/qa.md`. Падающие проверки чинить,
   а не объяснять.
7. **Отдать результат**: показать mp4, одной строкой перечислить допущения
   (подпись, длительность, палитра). Если пример был с Диска — загрузить
   аналог в ту же папку. В репозитории — закоммитить код, конфиг и результат.

## Зависимости

`pip install Pillow numpy imageio-ffmpeg` (ffmpeg — из пакета, системный
не нужен). Шрифты с кириллицей уже в `SKILL/assets/fonts` (OFL).

## Жёсткие правила

- Аналог ≠ копия: ритм и приёмы примера — да; чужая подпись, чужие
  формулировки и «честные числа» оригинала — нет.
- Текст в кадре обязан влезать и читаться на скорости сцены; проверка —
  полными кадрами, а не раскадровкой в миниатюре.
- Сумма длительностей сцен = длительности ролика; финал ≥ ~1.4 с.
- Не отдавать ролик без прогнанного `verify.py` и взгляда на раскадровку.

## Состав

- `scripts/render.py` — рендерер (сцены: hook_code, big_text, kinetic, cube,
  particles_text, counter, geometry, showreel, finale) + синтез звука.
- `scripts/analyze.py` — probe, кадры, раскадровка, спектрограмма, склейки.
- `scripts/verify.py` — проверки + раскадровка/обложка/отчёт.
- `references/` — разбор примера, формат сценария, устройство рендерера, QA.
- `examples/` — готовые конфиги: аналог разобранного шоурила и демо
  «другой сценарий/автор/палитра».
- Первую версию этого ролика (вне скилла, жёстко зашитая под одну задачу)
  см. в репозитории: `showreel/render.py` — скилл вырос из неё.
